# دليل فحص التفرد حسب الشركة — المرحلة الخامسة

**الحالة الحالية:** أداة فحص للقراءة فقط. تم تنفيذ قيود التفرد المركبة في Stage 10 / schema v6؛ ما زال فحص قاعدة بيانات فعلية مستعادة مطلوبًا قبل تطبيق الترحيل عليها.
**التاريخ:** 13 نوفمبر 2026

## الهدف

قبل استبدال قيود `UNIQUE` العامة بقيود نطاقها الشركة، يجب معرفة ما إذا كانت هناك مفاتيح مكررة داخل الشركة نفسها. الأداة الجديدة تقرأ نسخة SQLite محددة دون تعديل قاعدة البيانات، وتصدر ملخصًا ومجموعات التعارض مع أرقام الصفوف للمراجعة اليدوية.

## التشغيل الآمن

1. خذ نسخة احتياطية باستخدام إجراءات النسخ المعتمدة.
2. أوقف أي عمل قد يغير النسخة التي ستفحصها.
3. استعد النسخة الاحتياطية إلى **ملف منفصل**. لا تستخدم ملف قاعدة الإنتاج الحي.
4. شغّل الأمر من مجلد المشروع أو بأي مسار Python:

```bash
python backend/scripts/tenant_uniqueness_preflight.py /path/to/restored-copy.sqlite
```

لإنشاء تقرير JSON:

```bash
python backend/scripts/tenant_uniqueness_preflight.py /path/to/restored-copy.sqlite --output reports/tenant-uniqueness.json
```

القيم التجارية مخفية افتراضيًا. إذا احتجت إلى رؤية SKU أو أكواد الحسابات أو أرقام المستندات في التقرير، استخدم `--include-values` فقط مع حفظ التقرير في مكان خاص وآمن:

```bash
python backend/scripts/tenant_uniqueness_preflight.py /path/to/restored-copy.sqlite --include-values --output /secure/path/report.json
```

خيارات إضافية:

- `--max-groups 50`: يحدد عدد مجموعات التعارضات المعروضة لكل قاعدة (1–1000).
- `--fail-on-duplicates`: يرجع رمز خروج `2` إذا عثر على تعارضات.
- `--strict-schema`: يرجع رمز خروج `3` إذا تعذر فحص جدول أو عمود مطلوب.

## قواعد التفرد المشمولة

تفحص الأداة 15 قاعدة أعمال:

`accounts.code`; `attendance(employee_id,date)`; `categories.name`; `cost_centers.name`; `departments.name`; `depreciation_postings(asset_id,period)`; `journal_entries.number`; `payroll_runs.month` للقيود المنشورة فقط; `products.sku`; `products.barcode` عندما لا تكون القيمة NULL; `sequences.name`; `settings.key`; `stock_levels(product_id,warehouse_id)`; `trade_documents(doc_type,number)` عندما لا يكون الرقم NULL; `warehouses.code`.

تظل هوية الدخول `users.email` عامة، كما يظل كتالوج الأدوار `roles.name` مشتركًا في التصميم الحالي. لا تضف `company_id` إليهما بشكل آلي.

## تفسير النتائج

- `clear`: لا توجد مفاتيح مكررة داخل الشركة لهذه القاعدة في النسخة المفحوصة.
- `duplicates_found`: توجد مجموعة أو أكثر يجب مراجعتها يدويًا. يعرض التقرير الشركة وعدد الصفوف وأرقامًا نموذجية للصفوف.
- `ownership_missing`: يوجد صف واحد أو أكثر بقيمة `company_id` فارغة؛ يجب التحقيق في ملكيته قبل أي ترحيل.
- `missing_table` أو `missing_columns`: لا يمكن اعتبار هذه القاعدة مفحوصة؛ قد تكون قاعدة البيانات قبل الترحيل أو مخططها مختلفًا، أو عمود شرط جزئي مثل `status` غير موجود.
- `integrity_check` و`foreign_key_violation_count_sampled`: مؤشرات تشخيص إضافية، وليست بديلًا عن مراجعة الترحيل.

## حدود مهمة

- الأداة تفتح SQLite باستخدام `mode=ro` وتفعّل `PRAGMA query_only=ON`؛ لا تنفذ تعديلًا أو إصلاحًا أو حذفًا.
- لا تغيّر `SKU` أو أرقام القيود أو المستندات أو أي مُعرّف مالي تلقائيًا.
- لا تتجاهل الصفوف التي لا تحمل `company_id`؛ ستظهر كـ `ownership_missing` حتى لا تختفي من فحص التكرارات.
- لا تتحقق من أن استعلامات التطبيق وواجهات API والتقارير والملفات والمهام الخلفية معزولة حسب الشركة.
- القيود العالمية الحالية قد تمنع أصلًا وجود القيمة نفسها في شركتين؛ لذلك فحص التعارضات داخل الشركة لا يكفي وحده لإثبات صلاحية التصميم النهائي.
- التقرير الناتج صالح فقط للنسخة التي فُحصت. سجّل وقت النسخ الاحتياطي وبصمة ملف قاعدة البيانات مع التقرير عند تنفيذ فحص بيانات حقيقي.
- لا تنفذ ترحيل القيود الفريدة قبل تحليل نتائج نسخة مستعادة، ومراجعة العلاقات والفهارس والمشغلات التابعة لكل جدول.

## تحديث بوابة Stage 10

تم تنفيذ تحويل القيود في SQLite migration v6؛ ويشغّل الترحيل فحصًا إضافيًا يرفض المفاتيح المكررة داخل الشركة والصفوف بلا ملكية. الاختبارات المركزة على قواعد SQLite اصطناعية نجحت. **لم يُجرِ فحص على قاعدة بيانات إنتاج فعلية** لأن ملف قاعدة بيانات مستعادة لم يقدم.

قبل تطبيق v6 على قاعدة فعلية: خذ نسخة احتياطية، استعدها في ملف منفصل، شغّل أداة preflight بالأمر أعلاه، راجع أي نتائج غير `clear` يدويًا، ثم جرّب migration على النسخة المستعادة. لا توجد migration downgrade؛ إذا نجح تطبيقها ثم تقرر التراجع، استعد النسخة الاحتياطية السابقة. لا تغيّر أي SKU أو كود حساب أو رقم مستند تلقائيًا.
